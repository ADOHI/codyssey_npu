# Mini NPU Simulator

MAC(Multiply-Accumulate) 연산을 직접 구현해, 2차원 패턴과 필터의 유사도를 점수로 계산하고 Cross / X(또는 모드 1에서 A / B)로 판정하는 콘솔 프로그램입니다.  
과제 명세에 맞춰 **Python 3.8 이상**, **표준 라이브러리만** 사용합니다(NumPy, pandas 등 사용하지 않음).

---

## 실행 방법

1. 저장소 루트에서 다음 중 하나로 실행합니다.
   - **`python main.py`** (제출용 진입점: `src`를 경로에 넣고 `MiniNpuApp` 실행)
   - `python src/main.py` (`src`를 작업 디렉터리로 두었을 때와 동일한 효과)
2. 프롬프트에서 모드를 고릅니다.
   - **`1`**: 사용자 입력(3×3) — 필터 A, B와 패턴을 한 줄씩 입력
   - **`2`**: `data/data.json` 로드 후 일괄 분석
3. JSON 데이터 경로(모드 2): 프로젝트 루트 기준 `data/data.json`

**참고(Windows 콘솔):** 기본 코드 페이지(cp949)에서는 `✓` 같은 문자 출력 시 `UnicodeEncodeError`가 날 수 있어, 필터 로드 성공 메시지는 `[OK]`로 대체될 수 있습니다. UTF-8 터미널에서는 `✓`가 그대로 출력됩니다.

## 구현 요약(과제 요구 대응)

- **데이터 타입:** 필터·패턴 셀은 내부에서 **정수(`int`)** 로 통일합니다. JSON에 `1.0`이 있어도 정수로 변환 가능할 때만 허용하고, 콘솔 입력도 정수만 받습니다.
- **MAC:** 위치별 곱의 합. 외부 벡터화 라이브러리 없이 반복문으로 구현합니다. 실사용 판정·성능 표의 기준 함수는 `mac_score`(2D 이중 인덱스)입니다.
- **라벨 정규화:** 표준 라벨 `Cross`, `X`. `expected`의 `+` 등, 필터 키의 `cross` / `x` 등을 `normalize_label`로 통일합니다.
- **동점·부동소수점:** `abs(score_a - score_b) < 1e-9`이면 `UNDECIDED`(모드 2에서는 Cross vs X 점수, 모드 1에서는 A vs B 점수). 점수 본체는 정수여도 정책은 명세대로 유지합니다.
- **키·크기 일치:** `size_N` 또는 `size_N_idx`에서 뽑은 N과 행렬의 행·열 개수를 `validate_square_matrix`로 검증합니다. 불일치 시 해당 케이스만 FAIL 처리하고 프로그램은 계속 진행합니다.
- **성능 측정:** I/O 제외, `mac_score`(또는 변종 비교 시 해당 함수 본문)만 반복 호출 구간을 재며, 기본 **10회 평균**(`PERF_REPEAT`).
- **MAC 구현 3종 비교(보너스 성격):**
  1. **기본:** `pattern[i][j] * filt[i][j]` 이중 루프  
  2. **행 참조 캐시:** 행 참조를 로컬에 잡고 같은 행 내에서 곱·합  
  3. **1D 벡터 MAC:** 타이머 **밖에서** 한 번만 `flatten`한 뒤, 반복 구간에서는 `mac_score_flat`만 실행(변환 비용은 비교에서 제외)

## data.json 스키마(요약)

```json
{
  "filters": {
    "size_5": { "cross": [[...]], "x": [[...]] },
    "size_13": { "cross": [[...]], "x": [[...]] },
    "size_25": { "cross": [[...]], "x": [[...]] }
  },
  "patterns": {
    "size_5_1": { "input": [[...]], "expected": "+" },
    "size_13_1": { "input": [[...]], "expected": "x" }
  }
}
```

- 패턴 키는 `size_<N>_<idx>` 형태여야 하며, N에 맞는 `size_N` 필터가 있어야 합니다.

## 결과 리포트

1. **실패 원인 분류:** (가) 데이터·스키마: 잘못된 키, `filters`/`patterns` 구조 오류, `expected` 정규화 불가. (b) 크기·로직: 키의 N과 `input` 행렬 크기 불일치, 해당 `size_N` 필터 부재. (c) 수치·정책: `UNDECIDED`인데 `expected`가 Cross 또는 X라서 불일치 FAIL.  
2. **케이스 단위 FAIL:** 한 케이스가 잘못되어도 예외로 전체를 종료하지 않고, 메시지를 남긴 뒤 나머지 케이스를 계속 처리합니다.  
3. **라벨 정규화가 필요한 이유:** JSON·콘솔·과제 예시마다 `+`, `cross`, `x` 등 표기가 달라질 수 있어, 내부 비교와 PASS/FAIL은 반드시 `Cross` / `X`로 통일해야 집계가 일관됩니다.  
4. **epsilon의 역할:** 이 구현에서는 MAC 결과가 정수인 경우가 많지만, 명세대로 **허용 오차**를 두면 부동소수점으로 확장하거나 미세 오차가 생겨도 동점 처리를 일관되게 할 수 있습니다.  
5. **FAIL 0건인 경우:** 제공 `data.json`이 스키마·크기·라벨에 맞고, 판정 규칙이 기대와 일치하면 통과만 나옵니다. 이는 “데이터가 깨끗하고 정규화·epsilon 정책이 의도대로 동작했다”는 뜻으로 해석할 수 있습니다.  
6. **시간 복잡도:** MAC 한 번은 원소마다 곱·덧셈 1회이므로 **O(N²)** 입니다. N이 커질수록 연산 횟수는 N²에 비례해 늘어납니다.  
7. **성능 표 해석:** 모드 2의 `[3] 성능 분석`은 연산 횟수 열에 N²가 함께 출력되므로, 크기 증가와 평균 시간 증가의 방향을 같은 표에서 대응시켜 볼 수 있습니다.  
8. **모드 1 성능 표:** 사용자가 입력한 것은 3×3뿐이므로, 성능 표도 **3×3 한 행만** 출력해 입력 범위와 맞춥니다.  
9. **MAC 3종 비교 해석:** 세 구현 모두 같은 O(N²)이며, CPython에서는 N이 작을 때 **측정값이 노이즈에 민감**합니다. 1D MAC 행은 flatten을 **반복 밖에서 1회**만 하므로, 표에 찍힌 값은 “같은 곱·누적을 다른 접근으로 돌렸을 때의 상대적 경향” 참고용에 가깝고, 아주 짧은 시간(ms)의 부호만으로 최적화 결론을 내리기는 어렵습니다.  
10. **재현성:** 위 「실제 실행 출력」은 로컬에서 `python main.py`로 실행해 복사한 로그입니다. 모드 1은 A=1.0·B=5.0·판정 B로 수렴하고, 모드 2는 6케이스 모두 PASS, 총 테스트 6·실패 0입니다. ms 숫자는 실행마다 달라질 수 있습니다.  
11. **제약 준수:** MAC은 반복문 직접 구현, 외부 수치 라이브러리 미사용, 입력 검증 및 JSON 오류 시 비정상 종료 대신 케이스 단위 처리 등 과제 품질 기준을 맞추었습니다.

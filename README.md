# Mini NPU Simulator

## 프로젝트 개요
Mini NPU Simulator는 간단한 MAC(Multiply-Accumulate) 연산 기반의 필터 시뮬레이터입니다.  
3x3 ~ 25x25 크기의 패턴/필터에 대해 MAC 점수를 계산하고, Cross/X 판정 및 성능(연산 시간, 연산 횟수)을 분석하는 것을 목표로 합니다.

주요 기능:
- 콘솔에서 3x3 필터/패턴을 직접 입력해 MAC 점수와 판정을 확인
- `data.json`을 로드해 다양한 크기의 필터/패턴 케이스를 일괄 분석
- 라벨 정규화(Cross/X) 및 epsilon 기반 동점 처리 정책 적용
- 크기별 MAC 연산 시간 측정 및 `O(N^2)` 시간 복잡도 관찰

## 실행 방법
- Python 3.8 이상에서 실행합니다.
- 프로젝트 루트에서 아래 명령으로 실행합니다.
  - `python src/main.py`
- 실행 후 모드를 선택합니다.
  - `1`: 사용자 입력(3x3)
  - `2`: `data/data.json` 분석

## 구현 요약
- **MAC 연산**: 외부 라이브러리 없이 이중 반복문으로 `sum(pattern[i][j] * filter[i][j])`를 계산합니다.
- **라벨 정규화**:
  - `expected`: `+` -> `Cross`, `x` -> `X`
  - `filter 키`: `cross` -> `Cross`, `x` -> `X`
  - 내부 비교와 출력은 `Cross/X/UNDECIDED` 기준으로 통일했습니다.
- **점수 비교 정책**:
  - `abs(cross_score - x_score) < 1e-9`면 `UNDECIDED`로 처리합니다.
  - 그 외는 큰 점수를 가진 필터 라벨로 판정합니다.
- **입력 검증**:
  - 모드 1에서 행/열 개수 불일치, 숫자 파싱 실패 시 안내 문구 출력 후 재입력을 유도합니다.
  - 모드 2에서 스키마 오류, 크기 불일치, 키 규칙 오류는 케이스 단위 FAIL로 기록하고 프로그램은 계속 진행합니다.
- **성능 분석**:
  - 크기별 MAC를 최소 10회 반복해 평균 시간(ms)을 출력합니다.
  - 표에 `크기(NxN) / 평균 시간(ms) / 연산 횟수(N^2)`를 함께 출력합니다.

## data.json 스키마
```json
{
  "filters": {
    "size_5": { "cross": [[...]], "x": [[...]] },
    "size_13": { "cross": [[...]], "x": [[...]] },
    "size_25": { "cross": [[...]], "x": [[...]] }
  },
  "patterns": {
    "size_5_1": { "input": [[...]], "expected": "+" },
    "size_13_1": { "input": [[...]], "expected": "x" }
  }
}
```

## 결과 리포트
1. 실패 케이스는 크게 세 부류로 분리해 진단했습니다. 첫째는 데이터/스키마 문제(필수 키 누락, `size_N_idx` 형식 위반), 둘째는 로직 문제(크기 매칭 실패), 셋째는 수치 비교 문제(부동소수점 미세 오차)입니다.  
2. 스키마 문제가 있어도 전체 프로그램이 중단되지 않도록 케이스 단위로 FAIL 처리하여, 나머지 정상 케이스 결과를 계속 확인할 수 있게 했습니다.  
3. 필터 키와 expected 라벨의 표기 방식이 서로 다르면 PASS/FAIL 집계가 왜곡되기 쉬워, 정규화 레이어를 반드시 거치게 설계했습니다.  
4. 특히 `+`, `cross`, `x`처럼 표현이 다른 값을 표준 라벨(`Cross`, `X`)로 통일하면 비교 정책이 단순해지고 버그 가능성이 줄어듭니다.  
5. 부동소수점 연산에서는 이론상 같은 점수라도 표현 오차로 아주 미세한 차이가 생길 수 있습니다.  
6. 이 문제를 해결하기 위해 epsilon(`1e-9`) 기반 동점 판정 정책을 적용했고, 오차 범위 이내는 `UNDECIDED`로 처리해 잘못된 이진 판정을 방지했습니다.  
7. FAIL이 0개인 경우도 정규화와 epsilon 정책이 안정적으로 작동한 결과로 해석할 수 있으며, 이는 데이터 표현 차이와 수치 오차를 흡수했기 때문입니다.  
8. 시간 복잡도는 MAC 함수 기준으로 각 원소를 한 번씩 곱하고 더하므로 `O(N^2)`입니다.  
9. 실제 성능 표에서도 `3x3(9)` -> `5x5(25)` -> `13x13(169)` -> `25x25(625)`처럼 연산 횟수 증가와 평균 시간 증가가 같은 방향으로 나타납니다.  
10. 즉, 입력 크기 N이 커질수록 실행 시간은 대략 원소 수(`N^2`)에 비례해 증가하며, 본 시뮬레이터는 그 경향을 관찰하기 위한 최소 구조를 충족합니다.
